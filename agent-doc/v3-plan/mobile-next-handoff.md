# Mobile Next — Epic 7 Implementation Handoff

## Scope and baseline

The original implementation started from `6858291` on `develop`; the current integration baseline is recorded below. `apps/mobile-next` is a separate Expo 57 / React Native 0.86 app. **Do not delete, rename, migrate away, or edit `apps/mobile` as part of this work.** The final-swap section of the earlier Epic 7 plan is not authorized by the current task.

Business implementations are copied from v2, not redesigned. Feature APIs, query keys, queue semantics, SQLite schemas, playlist export formats, and native/web splits remain the source of truth. New pages use `@bilisound/ui` and Tamagui, without cross-app imports or NativeWind.

## Integration contracts

- Identity: `moe.bilisound.app.next.dev`; scheme `bilisound-next`; Metro port `8083`.
- Native OS sandbox isolates files/SQLite. MMKV instance names and web IndexedDB also have an explicit Next namespace. No automatic import from the old app; import/export remains the deliberate transfer path.
- Routes: `/` (query), `/playlist`, `/playlist/[id]`, `/playlist/meta/[id]` (`new` creates), `/settings`; feature-owned jumps retain `/video/[id]`, `/remote-list`, `/apply-playlist`.
- Common page adapter: `components/app-layout.tsx` wraps the shared `PageShell`; router behavior remains in the app.
- Common feedback: `components/feedback.tsx` renders the existing Toast transport through Tamagui and consumes the v2 transient error store.
- Layout switches at 768px: narrow bottom navigation and expandable Sheet player; wide sidebar and persistent player. Shared `DualScrollView` breakpoints are not changed globally.
- Theme registry keeps v2 storage/ID semantics, but drops NativeWind runtime variables. `BilisoundProvider` owns semantic light/dark palettes.
- Startup awaits initialization before rendering business routes; database failures are surfaced instead of allowing writes into an uninitialized database.
- Next does not auto-install v2 APK updates. This is a development application, not a replacement production release.

## Explicit parity decisions

- **Episode menu decision B:** restore export for the selected cached episode, including an episode that is not currently playing. Do not restore the v2 episode-menu delete action: it operated on the _current_ track rather than the selected episode. Current-track cache deletion stays in the player panel. Export uses the selected `bvid/page/title`, existing AV/BV naming preference and file helpers; cancellation gets neutral completion wording, not a false saved-success claim.
- **Theme editor:** sliders plus unbounded numeric offset entry preserve the v2 value domain, dynamic one-pixel minimum scale, 300% maximum scale, anchors, reset, and edit-session cancellation. They do **not** preserve direct dragging, pinch/wheel focal scaling or full-window WYSIWYG interaction. This is an explicit interaction replacement, not complete interaction parity. Native visual color selection is retained through `reanimated-color-picker`.
- **Development update channel:** Next intentionally has no v2 APK update/check-install flow. A read-only v2 update entry is also not carried over; license and credit pages are retained. No production swap, signing, publishing or infrastructure change is authorized.
